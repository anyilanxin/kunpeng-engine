# BPMN 2.0.2 分类相关标准定义整理

> 来源：`.agents/skills/bpm/Business Process Model and Notation.pdf`（BPMN 2.0.2, OMG 2013）。
> 所有定位（章节/表号/页码）均指该 PDF；引文为原文摘录，括注为中文说明。

BPMN 2.0.2 中与"分类"相关的标准定义共两套体系：

1. **流程类型分类**——结构化的、参与执行语义的流程分类（`processType` + `isExecutable`）
2. **元素级语义分类**——自由文本的、不参与执行语义的标注机制（`Category`/`CategoryValue`，配 `Group` 图形化）

---

## 1. 流程类型分类

### 1.1 专节定义 — §10.2.1 "Types of BPMN Processes"（p.147）

> "There are three basic types of BPMN Processes:"

| # | 类型 | 规范原文要点 |
|---|------|-------------|
| 1 | **Private Non-executable (internal) Business Processes** | 私有不可执行流程。"A non-executable Process is a private Process that has been modeled for the purpose of documenting Process behavior at a modeler-defined level of detail"——面向文档化，执行所需信息（如 formal condition Expressions）通常不含 |
| 2 | **Private Executable (internal) Business Processes** | 私有可执行流程。"An executable Process is a Process that has been modeled for the purpose of being executed according to the semantics defined in Clause 14"——按 Clause 14 语义执行。私有流程旧称 workflow/BPM process，Web 服务领域亦称 Orchestration of services |
| 3 | **Public Processes** | 公开流程。"represents the interactions between a private Business Process and another Process or Participant"——只保留用于与外部通信的 Activities 及其次序，内部活动不展示；可单独建模或在 Collaboration 中展示消息流。**"the public type of Process was named 'abstract' in BPMN 1.2"**（BPMN 1.2 时代叫 abstract） |

私有流程与池的约束（§10.2.1.1）：使用泳道类记法（如 Collaboration）时，私有流程装在单个 Pool 内，流程流不能跨界，消息流可以跨界。

### 1.2 XML 属性定义 — Table 10.1 "Process Attributes & Model Associations"（p.145）

**processType 属性：**

> `processType: ProcessType = none { None | Private | Public }`
>
> "Provides additional information about the level of abstraction modeled by this Process."（提供该流程所建模抽象层级的信息）
> - **Private**："A private Process is one that is internal to a specific organization."（特定组织内部）
> - **Public**："shows only those flow elements that are relevant to external consumers. Internal details are not modeled... can be used within a Collaboration."
> - **默认值 None**："By default, the processType is 'none,' meaning undefined."（未定义）

**isExecutable 属性：**

> `isExecutable: boolean [0..1]`
>
> "An optional Boolean value specifying whether the Process is executable."
> - **对 Public 流程的约束**："For public Processes, no value has the same semantics as if the value were false. The value MAY not be true for public Processes."——Public 流程缺省等同 false，且**不允许为 true**。

**supports 关联（流程细化关系，与抽象层级相关）：**

> `supports: Process [0..*]`
>
> "Modelers can declare that they intend all executions or performances of one Process to also be valid for another Process."——声明一个流程的所有执行同时也是另一流程的有效执行（细化的私有流程支撑其公开视图）。

### 1.3 XSD 定义（tProcess / tProcessType，XSD 章节引用于规范文末）

```xml
<xsd:attribute name="processType" type="tProcessType" default="None"/>
<xsd:attribute name="isExecutable" type="xsd:boolean" use="optional"/>
<xsd:element name="supports" type="xsd:QName" minOccurs="0" maxOccurs="unbounded"/>

<xsd:simpleType name="tProcessType">
  <xsd:restriction base="xsd:string">
    <xsd:enumeration value="None"/>
    <xsd:enumeration value="Public"/>
    <xsd:enumeration value="Private"/>
  </xsd:restriction>
</xsd:simpleType>
```

### 1.4 属性组合矩阵

| processType | isExecutable | 对应 §10.2.1 类型 |
|-------------|--------------|------------------|
| Private | true | Private Executable（引擎部署对象） |
| Private | false / 缺省 | Private Non-executable |
| Public | false / 缺省（不允许 true） | Public |
| None | 任意 | 未定义（缺省状态） |

## 2. 元素级语义分类（Category / CategoryValue）

### 2.1 用途定位 — §8.4.1 Group（p.67-68）与 Table 7.1（p.27）

> "Categories, which have user-defined semantics, can be used for documentation or analysis purposes."（具有用户自定义语义，供文档或分析用途）
>
> "Categories can be highlighted through other mechanisms, such as color, as defined by a modeler or a modeling tool."（可通过颜色等其他机制高亮）

即：Category 体系是**标注/分组机制，不参与执行语义**，属于 Artifact（制品）一族的支撑元素。

### 2.2 Category — Table 8.22 "Category model associations"（p.69）

| 属性 | 定义 |
|------|------|
| `name: string` | 分类的描述性名称 |
| `categoryValue: CategoryValue [0..*]` | 该分类的一个或多个取值。规范示例："the Category is 'Region' then this Category could specify values like 'North,' 'South,' 'West,' and 'East.'" |

Category 继承 BaseElement（经 RootElement），是**全局元素**（XSD 中 `substitutionGroup="rootElement"`），定义在 `<definitions>` 层，可跨图共享——"A single Category can be used for multiple Groups in a diagram."

### 2.3 CategoryValue — Table 8.23（p.69）

| 属性 | 定义 |
|------|------|
| `value: string`（可选） | 分类值 |

### 2.4 XSD 定义（Table 8.27 / 8.28，p.70-71）

```xml
<xsd:element name="category" type="tCategory" substitutionGroup="rootElement"/>
<xsd:complexType name="tCategory">
  <xsd:complexContent>
    <xsd:extension base="tRootElement">
      <xsd:sequence>
        <xsd:element ref="categoryValue" minOccurs="0" maxOccurs="unbounded"/>
      </xsd:sequence>
      <xsd:attribute name="name" type="xsd:string"/>
    </xsd:extension>
  </xsd:complexContent>
</xsd:complexType>

<xsd:element name="categoryValue" type="tCategoryValue"/>
<xsd:complexType name="tCategoryValue">
  <xsd:complexContent>
    <xsd:extension base="tBaseElement">
      <xsd:attribute name="value" type="xsd:string" use="optional"/>
    </xsd:extension>
  </xsd:complexContent>
</xsd:complexType>
```

### 2.5 图形化承载 — Group（Table 8.21 p.68 / Table 8.29 p.71）

Group 是 CategoryValue 的可视化形式：

> Table 8.21：`categoryValueRef: CategoryValue [0..1]` — "specifies the CategoryValue that the Group represents... The graphical elements within the boundaries of the Group will be assigned the CategoryValue."

```xml
<xsd:element name="group" type="tGroup" substitutionGroup="artifact"/>
<xsd:complexType name="tGroup">
  <xsd:complexContent>
    <xsd:extension base="tArtifact">
      <xsd:attribute name="categoryValueRef" type="xsd:QName" use="optional"/>
    </xsd:extension>
  </xsd:complexContent>
</xsd:complexType>
```

- 落在 Group 边界内的图形元素即被赋予该 CategoryValue
- Group 标签 = Category 名 + 分隔符 + CategoryValue 值。**注意：规范两处分隔符描述不一致**——§8.4.1 正文（p.68）写 `delineator ":"`，Table 8.21 写 `delineator "."`，引用时以所查版本原文为准
- Group 是纯图形分组："does not affect the Sequence Flows within the Group"（不影响组内顺序流）
- Group 可跨 Pool 框选不同 Pool 中的活动（Figure 8.14）

## 3. 引擎落地对位结论

| 需求 | 标准对位物 | 性质 |
|------|-----------|------|
| 流程的结构化类型（可部署执行 vs 文档化 vs 公开视图） | `processType` + `isExecutable`（§10.2.1 三分类） | 参与执行语义，枚举封闭 |
| 流程定义的业务分组（按部门/业务线等自由分类，用于流程库列表筛选） | `Category` / `CategoryValue`（definitions 层全局元素） | 自由文本、开放集合、不参与执行语义 |
| 公开视图与私有流程的关联 | `supports` 关联 + Collaboration 中引用 | 模型间关系 |

落地提示：引擎的流程分类字段若面向**检索/管理**，语义上是 Category 体系——标准中它是模型内标注而非流程属性，落库为部署元数据字段是工程化延伸，不与标准冲突；若面向**执行行为差异**，则应基于 processType/isExecutable，且注意规范约束"Public 流程 isExecutable 不允许为 true"。
