# 面板规范 — 指标名映射 / tag / 模板

`kunpeng.json` 面板撰写的全部硬规则。配合 SKILL.md 的五步流程使用。

## 1. 指标名 → Prometheus 名

Micrometer 经 prometheus registry 导出时的命名变换，写 expr 前先按此推导：

| 源类型 | 导出形态 | 面板引用 |
|--------|---------|---------|
| `Type.GAUGE` | 原名（`.`→`_`） | 直接引用 |
| `Type.TIMER` | `<name>_seconds_count` / `_seconds_sum` / `_seconds_max` | 均值=`sum(rate(_seconds_sum[5m])) / sum(rate(_seconds_count[5m]))`；峰值=`max(_seconds_max)` |
| `Type.COUNTER` | `<name>_total` | 速率=`rate(<name>_total[5m])`；累计增量=`increase(<name>_total[10m])` |
| `Type.DISTRIBUTION` / UNKNOWN | 原名或多种 | 按实际导出选 |

已踩过的坑：
- `atomix_election_latency_in_ms` 是 **GAUGE**（名字带 ms 但无 `_seconds_` 后缀）；
- `atomix_heartbeat_time`、`atomix_compaction_time_ms` 是 **TIMER**（导出 `_seconds_*`）；
- `kunpeng_engine_timers_lag` 是 **TIMER** 不是 gauge；
- micrometer 未配直方图时**没有分位数**（无 `_bucket`），延迟面板只用 均值/最大，不要写 `histogram_quantile`。

## 2. tag 键总表（expr 的 by 维度）

| 指标族 | tag 键 | 备注 |
|--------|--------|------|
| raft 角色层（role/term/election） | `partitionGroupName` | RaftRoleMetrics 只带组名 |
| raft 复制层（append/commit/lag） | `partitionGroupName`, `partition`, `follower` | by 里带上才有 per-follower 曲线 |
| journal / 分区索引 / 启动耗时 | `partition` | |
| eventlog | `log`, `partition`, `context`, `reason` | |
| scheduler | 无定制 tag（按 job 聚合） | |
| sink | `partition`（PartitionKeyNames）, `sinkId`, `action`, `type` | action=delivered/skipped |
| SWIM | `memberId` | |
| engine timers | `partition`, `intent`（dedup） | |
| 所有指标 | `job`（Prometheus scrape job）, `pod`, `namespace` | prometheus.yml 里的 static labels |

## 3. 枚举值映射（面板需要 value mapping）

- Raft 角色 `atomix_role`：0=INACTIVE 1=PASSIVE 2=PROMOTABLE 3=FOLLOWER 4=CANDIDATE 5=LEADER（`RaftServer.Role` 声明序）；角色面板用 `state-timeline` + mapping；
- Sink 相位 `kunpeng_sink_phase`：0=running 1=paused 2=soft paused 3=closed；用 `stat` + background 色映射。

## 4. 面板类型与常用套路

- 数值概览 → `stat`（h=4，w=6）；时间序列 → `timeseries`（h=8，w=6/8/12/16/24）；角色/相位演变 → `state-timeline`。
- 单位：延迟 `s`、速率 `ops`、字节 `bytes`/`Bps`、比率 `percentunit`（max=1）、计数 `short`。标题已含单位的用 `short`，不要乱配 Grafana 单位 id。
- 同主题多 series 合一个面板（如段操作四类耗时）；同一指标多维度分面板。
- 水位差类用 `clamp_min(a - on (job, partition) b, 0)`；跨指标族 join 用 `group_left (sinkId)`。

## 5. 面板 JSON 模板

timeseries：

```json
{
  "datasource": {"type": "prometheus", "uid": "${DS_PROMETHEUS}"},
  "description": "可选：一句话说明看什么",
  "fieldConfig": {"defaults": {"unit": "s"}, "overrides": []},
  "gridPos": {"h": 8, "w": 8, "x": 0, "y": 0},
  "id": <全文件唯一，顺延>,
  "options": {"legend": {"displayMode": "list", "placement": "bottom", "showLegend": true},
              "tooltip": {"mode": "multi", "sort": "desc"}},
  "targets": [{"datasource": {"type": "prometheus", "uid": "${DS_PROMETHEUS}"},
               "expr": "<PromQL，必含 job=~\"$job\">", "legendFormat": "{{label}}", "refId": "A"}],
  "title": "中文标题（含单位）",
  "type": "timeseries"
}
```

stat：把 `fieldConfig.defaults` 换成 `{"unit": "short", "mappings": [{"options": {...}, "type": "value"}]}`，`options` 换成 `{"colorMode": "value", "graphMode": "area", "reduceOptions": {"calcs": ["lastNotNull"], "fields": "", "values": false}}`。

新增面板放对应分节 row 之后、下一个 row 之前，`gridPos.y` 顺延该节已有面板（或直接重排该节 shelf：24 列宽逐行装箱）；row 面板形态 `"type": "row"`、`"collapsed": false`、`w=24, h=1`。

## 6. 变量

面板引用的五个模板变量已在 dashboard 顶层 `templating` 定义，新面板直接用：

| 变量 | 含义 | 来源 label_values |
|------|------|------------------|
| `DS_PROMETHEUS` | 数据源 | datasource 类型 |
| `job` | 节点（gateway/broker-N） | `up{job=~"kunpeng.*"}` |
| `partition_group` | Raft 分区组 | `atomix_role` |
| `partition` | 分区 id | `eventlog_position_written` |
| `sink_id` | 外发通道 | `kunpeng_sink_position_delivered` |
