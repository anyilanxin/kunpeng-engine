# 02 — structpack 性能报告

> 模块：`kunpeng/structpack` | 数据：JMH 基准实测（方法：预热 30 万触发 C2 + 5 轮 × 20 万取最优、轮间交替测量顺序；round-trip 正确性先断言后计时）

## 1. Record 帧性能（7 字段同构 Record，实测区间 6 次独立运行）

| 指标 | 实测 | 说明 |
|---|---|---|
| **编码体积** | **54 B** | 确定性，零波动 |
| **读入** wrap+reset | 300–387 ns/op | id 数组直读 |
| **写出** fill+write | 347–369 ns/op | 占位回填（方案 A+C+D） |
| 纯 write（分解） | 166–168 ns | 布局缓存后零分配 |
| getEncodedLength（分解） | 94 ns | 前缀尺寸计算（格式必需） |

### 体积账本（7 字段实例，可手工复算）

```text
54B = magic/ver 3B + 字段数 1B + id 列表 7B + Σ[值长度 1B + 值] + 未声明数 1B
      （key 开销 = 0；id 每字段 ~1B）
```

系统级含义：Raft 复制带宽、RocksDB 空间、网络传输正比于帧体积——字段越多、key 越长，id 化的收益越大。

### 读快写平的结构原因

- 读：id 数组直读（1 次 varint 读 + 数组下标），未知 id 按长度 O(1) 跳过——零字符串比较零哈希查找。
- 写：上限是写字节速度本身；长度前缀的固有写入成本是"未知 id 可跳过"的必要代价。

## 2. 设计迭代决策记录

| 候选格式 | 体积 | 读 | 否决原因 |
|------|------|-----|----------|
| 位置帧 | 40B | 1.2–1.5x | 需尾部追加纪律 |
| key-wire 无 tag | 79B | 0.88–0.94x | ghost 必需 |
| key+tag 自描述 | 86B | — | 零仪式但全面落后 |
| key-id 无前缀 | 47B | 1.26–1.33x | 删除需 declareGhost |
| **key-id 自界定帧（定稿）** | **54B** | **1.14–1.28x** | — 零 ghost，双向互读 |

写路径优化轨迹：方案 A（占位回填）→ C（advance 跳占位写 + 布局期数组缓存）→ D（gLen 单循环）：
0.83–0.90x → 0.94–0.96x → 0.93–1.03x（相对基准形状）。方案 D 的发现依据是分解测试——"写慢"真凶是 getEncodedLength（List.get 虚调用 + 双循环），非 write 本身。

## 3. DocumentCodec 性能（document 编解码，自研实现）

`DocumentCodec`（~330 行，零外部依赖）输出与标准 msgpack 字节逐字节一致（硬断言通过）。实测：

| 文档形状 | 体积 | 打包 | 解包 |
|----------|------|------|------|
| small（5 字段扁平） | 75 B | **195 ns** | **356 ns** |
| medium（10 字段+嵌套+明细） | 243 B | **847 ns** | **1541 ns** |
| large（3 层+20 标签+12 指标） | 1670 B | **4576 ns** | **8053 ns** |

实现要点：直接操作可增长 byte[]、单遍直读，无多层流抽象、无格式预读。JSON 解析走 Jackson 3。

## 4. JSON 桥接技术选型记录（2026-08 实测，结论：Jackson 不换）

Apache Fory 1.4.0 宣称 JSON 比 Jackson 快 5x，但在 DocumentUtil 的真实形态（`Object.class` 无类型树解析 + 树写回，~450B 中文混合文档）实测：解析 1.00–1.16x（持平）、写回 1.25x，端到端仅 ~5–10%。不换理由：

1. 5x 宣告依赖按声明类型的运行时代码生成；无类型树走手写 `readUntyped` 路径
2. JSON 桥接只在网关 API 边缘，不在引擎热路径；单次绝对差 ~400ns 无感知
3. 1.7.0-SNAPSHOT 需自行构建发布，运行时引入 5 个依赖；该路径是与 gateway/job API 互通的关键路径，风险集中

## 5. 当前守卫状态

- 测试套件：`./gradlew :kunpeng:structpack:test` → **117/117 全绿**（14 测试类 + sample）
- id 守卫：编译期（无 id 构造器不存在）+ 构建期（AutoDeclarePropertiesTask：1..127、禁重复）+ 运行时（declareProperty 拒 id≤0）
- 性能回归守卫：如需重建，应以绝对基线（宽阈值）或内部对照形式设计
