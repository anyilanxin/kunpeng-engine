# 01 — structpack 实现原理

> 模块路径：`kunpeng/structpack`
> 状态：v1 key-id 自界定帧定稿。structpack 是引擎唯一 Record 序列化层。

## 1. 设计目标

| 目标 | 含义 | 达成手段 |
|------|------|----------|
| 极致性能 | 读路径 id 数组直读（零字符串比较零查找）；写出与字节速度同阶 | key-id 帧 + varIntLength 静态长度计算 + 占位回填 |
| 零拷贝 | 字符串/二进制/文档读入为 buffer 视图，不复制字节 | agrona `UnsafeBuffer.wrap` 视图 |
| 零分配 | Record 实例 `reset()` 后重用；容器/未声明槽位池化 | 槽位池 + `Recyclable` 语义 |
| 演进自由 | 字段任意位置增删；新旧版本双向互读互不失败 | id 身份（构造首参）+ 值长度前缀自界定 |
| id 强制 | id 必然存在且合法（1..127） | 无 id 构造器不存在 + 构建任务守卫 + 运行时守卫 |
| document 兼容 | 流程变量与外部 API 互操作零转换 | 内容保持标准 msgpack（自研 DocumentCodec 编解码） |

## 2. 总体架构（五层）

```text
┌─────────────────────────────────────────────────────────┐
│ 入口层  UnpackedObject (extends ObjectValue)             │  Record/Entity 基类
│         wrap(buffer)/write(buffer,off)/getLength/reset   │
├─────────────────────────────────────────────────────────┤
│ 槽位层  BaseProperty + 16 个子类                          │  id + key + 值载体 + 默认值 + isSet
│         Long/String/Enum/Array/Document/Undeclared/...   │
├─────────────────────────────────────────────────────────┤
│ 载体层  BaseValue + 15 个子类                             │  纯数据与编解码
│         LongValue/StringValue/.../MapValue                │
├─────────────────────────────────────────────────────────┤
│ 编解码层 PackerWriter / PackerReader                      │  varint/zigzag/裸原语
│         TAG_* 常量 + skipTyped() 通用跳过                 │
├─────────────────────────────────────────────────────────┤
│ 工具层  DocumentUtil + DocumentCodec / BufferUtil         │  document 走标准 msgpack 字节
└─────────────────────────────────────────────────────────┘
```

Property/Value 分层语义：**Property 管 id、key、默认值、isSet（业务契约）；Value 只管数据与编解码（纯机器）**。

## 3. wire 格式 v1（key-id 自界定帧）

```text
Record := MAGIC(0x4B 0x50) VER(0x01)
         FIELD_COUNT varint
         [FIELD_ID varint 严格升序 ...]   // id 定义于 Property 构造首参, ~1B/字段
         [VALUE_LEN varint VALUE]*        // 值自界定: 已知按类型解析, 未知按长度跳过
         UNDECLARED_COUNT varint
         { KEY_LEN varint KEY bytes 带 tag VALUE }*
```

undeclared 逃逸值 tag（`PackerReader.TAG_*`）：NIL/VARINT/DOUBLE/FLOAT/BOOL/BYTES/ARRAY/NESTED；读方无需理解内容即可 `skipTyped()` 跳过并原样写回。

### 极简帧示例

`Point{x=1(id1), y=-1(id2)}` → `4B 50 01 | 02 | 01 02 | 01 02 01 01 | 00` = **11 字节**：
- `4B 50 01`：magic + 版本；`02`：2 个字段
- `01 02`：id 列表（严格升序 = 规范写出序）
- `01 02`：值长度 1 + zigzag(1)=2；`01 01`：值长度 1 + zigzag(-1)=1
- `00`：未声明区为空

## 4. 关键机制

### 4.1 字段身份：id 强制存在，三重守卫

```java
final LongProperty orderId = new LongProperty(1, "ORDER_ID", -1);
// id/key/类型/默认值同在一行; declareProperty(orderId) 链保持干净
```

| 守卫层 | 机制 |
|--------|------|
| **编译期** | 全部 Property 类（含 BaseProperty）只有 id-first 构造器——不传 id 无法通过编译 |
| **构建期** | `AutoDeclarePropertiesTask` 校验 id ∈ 1..127、严禁重复；缺失自动分配插入 |
| **运行时** | `ObjectValue.declareProperty` 拒绝 `id <= 0`；构造期校验 id/key 均唯一 |

- 新字段零仪式：初始化器不写 id → 构建任务自动分配**最小未用正整数**插入首参；
- **删除字段 = 直接删那一行，零额外动作**：id 由 `// structpack-ids[类名]: ...` 标记注释自动退休（累积制只增不减，永不复用）；旧数据中的已删字段被读方按值长度直接跳过；
- **值自界定**：每值带长度前缀——未知 id（新版本字段/已删字段）读长度直接跳过，新旧版本双向互读互不失败，无 ghost/载体声明；
- key 改名 = 新字段（同删除+新增）；字段类型不可变更。

### 4.2 读路径：按 id 数组直读 + 未知 id 按长度跳过

```java
// 布局: FIELD_COUNT + [FIELD_ID 严格升序...] + [VALUE_LEN VALUE]*
// id 块: 升序违例 = 数据损坏, 立即抛出
// 值块: 每值先读长度前缀;
//   已知 id → slotById[id] 数组下标定位 → declared.read(reader)（忽略前缀按类型解析）
//   未知 id → reader.skipBytes(length) —— 新版本字段/已删字段一律跳过, 永不失败
```

- **零字符串比较、零哈希查找**——id 是一次小 varint 读 + 数组下标。
- 读后校验：未覆盖且无默认值的字段抛 `StructPackException`（不静默给 0）。
- 越界防护：`PackerReader.ensureRemaining` 在每个原语前校验，截断数据必抛（测试覆盖每个截断位置）。

### 4.3 写路径：规范 id 序 + 占位回填

写出按 **id 严格升序**（构造期懒构建布局缓存，一次性）——同一条记录在任何节点、任何声明序的类上字节级一致（Raft 幂等/字节比较的前提，有测试）。写路径优化：

- **方案 A 占位回填**：每字段 `advance(1)` 预留长度位 → 写值 → 回填实际长度——免二次长度测量。值 < 128B 单字节回填；值 ≥ 128B 值整体右移扩展前缀后回填 varint（重叠安全自尾向头）。
- **方案 C 写循环优化**：声明槽位数组于布局期缓存（写路径零分配、消除循环内 `List.get` 虚调用）。
- **方案 D getEncodedLength 优化**：单循环合并 + 数组缓存——write 与 gLen 同享布局缓存。
- 写前 `ensureWritable()` 校验所有 declared 字段有值或默认值，**无值即抛，不静默丢字段**。

### 4.4 构建任务（id 模式）

`AutoDeclarePropertiesTask`（buildSrc，插件 id `kunpeng.auto-msgpack-declare`）对 import 含 structpack 包的类：**向字段初始化器插入/校验 id 首参** + 生成 `declareProperty(field)` 链 + 维护 `// structpack-ids[类名]: ...` 标记注释：

| 场景 | 任务行为 |
|------|----------|
| 新字段（初始化器无 id） | 分配最小未用正整数（跳过标记中全部已退休 id）插入首参，更新标记 |
| 删除字段 | **零动作**：标记累积制自动退休该 id（永不复用），构建照常通过 |
| id 重复 / id ∉ 1..127 | **构建失败**（1 字节保证；含手写 0/负数） |

样例：`com.anyilanxin.kunpeng.structpack.sample.SampleRecord`（测试源码，含删除纪律演示）。

### 4.5 生命周期安全

- declared 的字符串/二进制/文档值是**源 buffer 视图**（零拷贝）——源 buffer 在对象 reset 重读前不可回收改写。
- `UndeclaredProperty` 的 key 与 tagged value **拷贝进自有 byte[]**——源 buffer 回收/复用后仍可安全写回（有测试）。

### 4.6 池化复用

`ArrayValue`/`SetValue`/`MapValue` 元素槽位、`ObjectValue` 的 undeclared 条目均带归还池：`reset()` 归还，下次读入从池取。稳态读写循环零分配（有工厂调用计数测试）。

### 4.7 document（流程变量）双轨策略

`DocumentValue` 内容**保持标准 msgpack 字节**，structpack 只做字节级透传永不解析；JSON/Map 互转由 `DocumentUtil` 承担，其 msgpack 编解码由**自研 `DocumentCodec`**（~330 行，零外部依赖）完成——写侧与官方 msgpack-java 默认 packer**字节完全一致**（gateway/job API 直接互读）。JSON 解析走 Jackson 3。性能见 [02-性能与演进.md](./02-性能与演进.md)。

## 5. 约束与代价

- ⚠️ **字段身份契约**（纪律，均有守卫）：① 同一实体 id 与 key 唯一且**已删除 id 永不复用**（标记注释累积制）；② 字段类型不可变更；③ id ∈ 1..127。
- ⚠️ **互操作**：structpack 帧仅本引擎可读；跨系统交换走 document（标准 msgpack 字节）或网关 JSON。
- ⚠️ **生命周期**：declared 视图依赖源 buffer 存活；undeclared 已自有拷贝不受限。
- 未声明字段读写是字节透传——引擎侧无法按名取用（逃逸区不是动态字段）。

## 6. 开发指南

- 新 Record/Entity：字段写 `new XxxProperty(id, KEY, 默认值)`（id 可省略，构建任务自动插入）→ 类上 `@AutoDeclareProperties` → 构建任务生成 `declareProperty` 链。写法参见 [../编码规范/](../编码规范/Index.md)。
- 删除字段：删那一行即可；改名 = 删除 + 新增；唯一硬约束是 id/key 唯一与类型不变。
- document/流程变量：构造 `new DocumentProperty(id, "KEY")`，JSON 互转用 `DocumentUtil.convertToMsgPack/convertToJson/convertToMap`。

## 7. 开发中修复的主代码缺陷（留档）

| 缺陷 | 修复 |
|------|------|
| `EnumValue.read` 对 -1（null 编码）抛"ordinal 越界" | read 显式接受 -1 → null |
| 容器 Property `hasValue()=true` 但 `resolveValue` 未 set 即抛 | Array/Set/Map/ObjectProperty 重写 `resolveValue` 直接返回 value |
| 标量 Value 无 equals/hashCode | 7 标量 + EnumValue 按语义补齐 |
| `DocumentUtil` 非法 msgpack 抛裸异常 | 包装为 `IllegalArgumentException` |
| `ObjectValue.VERSION`（int）遮蔽实体的 `RecordConstant.VERSION`（String）静态导入 | 重命名 `WIRE_VERSION` |
| DocumentCodec 宽容器头缺长度字段（≥16 元素） | writeContainerHeader 附带 u16/u32 长度 |
